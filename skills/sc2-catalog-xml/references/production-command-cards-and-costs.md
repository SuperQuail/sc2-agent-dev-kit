# 生产、命令卡与费用注意事项

按 `单位 → 技能 / 武器 → 效果 → 行为 / 验证器 / 需求` 追，然后把生产者、按钮、Actor、Model、Sound、Mover、Turret 与本地化放进同一次改动。

## 核验顺序

1. 生产者的 `AbilArray`
2. 生产技能的 `InfoArray`
3. 目标 `Unit`
4. 按钮 `Face`
5. `Type="AbilCmd"` 配确切的 `AbilCmd`
6. 实际卡布局与继承的槽位
7. `Show`/`Use` 需求

光有可见的名字/提示框，只证明 `Face` 有效——不证明费用/时间命令链接有效。

## 命令卡与子菜单

- 同坐标的阵营按钮靠互斥需求工作——按钮和命令卡条目都要查，确保当前玩家只有预期那一个是活动的。
- 保留继承的 `Attack`/`Stop`/`Rally`/变形槽位。
- 工人子菜单必须同时匹配 `CardLayouts index` **与** `CardId`——只追加一个同名的子卡是不够的。
- 带武器的单位仍然需要有效的 `Attack` 技能；移动/折跃还需要 `Move`/`Warpable`。
- 复制技能时，审计 `Smart`、`SmartPriority` 与 `SmartValidatorArray`，免得右键被截走。
- 自动施法过滤器处理通用目标属性；精确的单位集合或数量条件用验证器。脚本化的副作用要核验实际的施法者与目标事件。

## 费用与显示注意事项

- 优先用原生费用显示；不要把升级变量数字硬编码进提示框。
- **不要为了显示价格就把单位费用重复写进 `InfoArray.Resource`。** 源文档在这里自相矛盾（[references/production.md](production.md) 前面要求一致，后面又说它是在费用之上的增量）——对照当前父级链与游戏内测试确认。
- 批量生产时，先查原始 `Resource`，再算批量总费用；变形可能涉及费用差值。
- `CostResource` 的 `Multiply` 据报不适用——优先用既有的 `Add`/`Subtract`/`Set` 示例，并对实际数据核验。

## 折跃与升级

- 同一建筑上共享一次折跃机会的多个 `CAbilWarpTrain`，必须共用一个 `Location=Unit` 的充能链接——否则会出现跨技能绕过冷却，或所有建筑共享冷却的 bug。
- `WarpTrain` 里重复的 `Unit` 子项会被编辑器在保存时规范化；多单位产出需要独立的完成阶段逻辑，而不是标准的 `Train` 批量示例。
- 非星灵折跃单位：核验 `Warpable`、出生/建造 Actor、`BuildModel` 与完成阶段——普通训练成功不证明折跃成功。
- 每种形态都要核验科技允许状态。按级武器/护甲升级要逐级、逐形态审计；如果共享的伤害效果已被某个原版升级改过，不要再叠同一个数字。
- 新 `CUpgrade` 行：不要把 `parent` 当依赖或解锁。原版战役 Bank 触发器可能单独授予原版升级并与自定义效果叠加——两条授予路径都要测。
