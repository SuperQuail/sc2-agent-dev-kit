# AI 性格波次转 GUI 触发器

当 SC2 组件地图把攻击波放在 AI 模块（`CustomAI`）里，而用户想要等价的、可编辑的触发器编辑器逻辑时，用这条工作流。目标是行为迁移，不是简单复制生成的 Galaxy。

## 来源与归属

- 把 `CustomAI` 当作以下内容的来源描述：性格、来源/目标玩家、集结点、波次顺序、难度取值、抵达/集结时机、创建点、路径点、目标点，以及末波重复。
- 把地图的 `Triggers` 与本地化的 `TriggerStrings.txt` 当作可编辑的目标。
- 只在理解生效行为与初始化时才读生成的 `ai<ID>.galaxy` 与 `MapScript.galaxy`。绝不编辑它们；编辑器会重新生成。
- 把 AI 性格的攻击波调度器与战役 AI 本身区分开。移除性格时绝不能顺带移除其来源玩家的 `AICampaignStart`。

## 预检

1. 确定确切的 `.SC2Map` 组件目录，并确认它已在 SC2 编辑器中关闭。
2. 备份 `Triggers`、`TriggerStrings.txt`，以及在最终移除性格之前备份 `CustomAI`。
3. 解析 `CustomAI` 并记录：
   - 定义 ID 与来源/目标玩家；
   - 默认集结点与末波重复次数；
   - 每一波的单位 ID 与四档难度数量；
   - 时机语义（`Arrival`、`GatherTime`）、创建模式/点、路径点顺序与目标点；
   - 任何步骤触发器或自定义数据钩子。
4. 查看同一张地图里既有的 GUI 攻击波触发器，复用它们真实的函数 ID、参数形态、子函数类型、preset 与位置引用写法。不要凭名字臆造 ID。

## 构建 GUI 触发器

为每个迁移的性格创建一个普通、无事件的触发器。找到地图既有的 AI 编排触发器（通常叫 `Start AI`），在那里用不等待的 GUI `Run Trigger` 动作运行每个迁移触发器。不要给迁移波次触发器另加地图初始化事件。

- 保留波次顺序与时机语义。抵达间隔并不自动等价于一个裸 wait；对照生成的性格代码与相邻任务触发器。
- 使用相同的来源玩家、目标、集结点、创建点、路径点序列与发送模式。
- 给每个迁移主触发器和每个 `Attack Wave <id> Async` 辅助触发器加一个本地整数 `aiPlayer`，一次初始化为该性格的来源玩家，并让该触发器里每个进攻玩家 GUI 参数都引用它。不要把同一个进攻玩家编号字面量重复写进攻击波目标、集结、路径点、创建、使用编组与发送动作。另一个目标玩家的 `PlayerGroupSingle(1)` 取值要保持独立。
- 对一个常量目标玩家组只初始化一次，用 `PlayerGroupSingle(1)` 的 GUI 等价写法，并在迁移触发器里全程复用。递归检查循环、条件分支与异步辅助触发器。在每一层嵌套里移除针对未变目标的「清空加添加」动作；在性格主触发器里把那条单独赋值提升（hoist）到性格停止动作之后，而在异步辅助触发器里，在它开头等待之后就地替换该配对。目标/集结/路径点设置是另一回事：它们配置的是当前正在组装的波次，每次发送后的新波次都必须重新设置。
- 用地图既有的 GUI 难度取值函数表达依赖难度的数量，然后对得到的单位数量表达式套上已配置的攻击波修饰器。
- 对原生 `AIAttackWaveAddUnits4`，按语义难度把编辑器的四个字段绑到真实参数定义上：easy `24D9A2D7`、normal `B52CD455`、hard `AD14DE85`、expert/brutal `A166DBF3`。不要按 XML 参数引用顺序赋值；对着编辑器字段标签确认映射。
- 对使用 `CreateUnits` 的波次，在记录的点创建单位，把得到的组放进攻击波，然后设置路径点/目标并发送。
- 用 GUI 重复/while 容器复现末波循环。每个嵌套动作都必须带上该地图某个已知可用循环所用的确切子动作 `SubFunctionType`。缺子类型会让编辑器把该动作当孤儿移除，随后把它的参数报成无效引用。
- 给每个新 `Element` 一个全新的八位大写十六进制 ID。一个函数调用元素只能有一个父引用；要克隆子树，不要共享。
- 用 `TriggerStrings.txt` 既有的语法与编码，为新触发器/局部变量元素加上可读名字。
- 从 `ObjectStrings.txt` 的 `AI/Name/<definition-id>` 键解析每个性格的显示名，并把主触发器命名为 `<性格名> Attack Waves`（例如 `Protoss P02 Attack Waves`）。显示名缺失要当错误处理；不要拿内部十六进制 ID 顶替。
- 移除在脚本动作被换成 GUI 树之后不再被引用的局部变量；尤其当所有产出的点参数都是直接的 GUI 点引用时，不要留下未使用的 `createPoint` 变量。
- 标准转换用 `scripts/convert_custom_ai_to_gui.py`。它的目标产物对迁移波次必须只含 GUI `FunctionCall` 与 `Param` 元素；绝不把中间态的 `ScriptCode` 迁移交给用户。
- 如果地图已含有标记为 `Codex migrated AI personality` 的遗留中间态迁移，就就地转换那个既有攻击波触发器。保留每一处既有修饰器输入，只从该迁移攻击波触发器上移除地图初始化事件，把它从内部 ID 改名为性格显示名，并接进 `Start AI`。不要从 `CustomAI` 重建它的波次体，也不要再套一次数量缩放。
- 把 `convert_custom_ai_to_trigger_scripts.py` 当作私有的兼容阶段，把 `convert_migrated_scripts_to_gui.py` 当作修复辅助。不要直接在用户的地图上调用兼容阶段。

## 切换策略

从以下明确策略里选一个；不要留下两套同时在跑的调度器。

### 分阶段切换（首次编辑器往返的首选）

暂时保留 AI 性格。在替换触发器开头，调用地图里停掉该性格波次的 GUI action，然后运行迁移过来的 GUI 序列。这样便于比对，也避免在新触发器被编辑器接受之前就删掉生成的性格支撑。

对地图里其他每一处会停掉该遗留性格的动作，都镜像补一个指向迁移波次触发器的 GUI `Stop Trigger` 动作。不要换成按玩家全停攻击波：无关的脚本波次触发器可能用的是同一个玩家。把迁移触发器自身开头那个「停性格」动作排除在外，免得替换触发器把自己停掉。

### 最终清理

GUI 触发器被编辑器接受并在运行时测过之后：

1. 在编辑器里从 AI 模块删除该性格；不要手工删 `CustomAI` 或 `ai<ID>.galaxy` 文件。
2. 移除替换触发器里的「停性格」动作，免得它变成无效引用。
3. 确保来源玩家仍然收到正常的战役 AI 启动动作。如果删除性格后不再生成它，就把它加到地图初始化里。
4. 在编辑器里保存，并确认生成的地图脚本包含新触发器注册、来源玩家的战役 AI 启动，以及没有任何对被删性格的调用。

把「重复末波」设为 0 只会禁用重复；它不会禁用更早的性格波次。关闭 AI 模块窗口同样不会禁用该性格。

## 结构校验

把地图交回之前：

- 把 `Triggers` 当 XML 解析；
- 拒绝重复的 `Element/@Id`；
- 确保每个新 FunctionCall 恰好被其父级引用一次；
- 确保嵌套循环动作带有该地图合法的子 `SubFunctionType`；
- 确保每个被引用的参数与函数调用 ID 都有声明；
- 确保迁移的性格触发器没有事件，且既有 AI 编排触发器不等待地各运行它们恰好一次；
- 确保迁移触发器里不含 `ScriptCode`（本工作流强制要求纯 GUI）；
- 核验每个生成调用的直接 `ParameterDef/@Library` 与其 `FunctionDef/@Library` 一致；LotV 难度参数必须用 `Library="Lotv"`，`AttackWaveModifier` 的输入 `4D4D221F` 必须用拥有它的模组库（默认配置档里是 `67AA1763`），绝不能用 `Ntve`；
- 跑 `scripts/wrap_attack_wave_counts.py <Triggers> --check`，确认所有受支持的数量参数都被包裹；
- 对着 `CustomAI` 比对波次数量、顺序、单位编成、难度取值、延时、点位与重复。
- 比对时要把性格自有的 `Attack Wave <id> Async` 辅助触发器算进去，并在主触发器运行它们的地方展开。`NoWait` 的波次单位就在那些辅助触发器里，它们不在主触发器体里并不代表缺失。

静态校验不证明编辑器接受。要求一次编辑器打开/保存往返、查看告警、检查重新生成的 `MapScript.galaxy`，并至少测两档难度。分阶段切换期间，还要确认只有一个调度器在发波。
