# Galaxy 代码组织与文件拆分

SC2 地图里的 Galaxy 脚本可以用 `include` 拆到多个 `.galaxy` 文件。这样代码更易维护、更模块化。**SC2-IngameDevTools 模组是文件结构与模块布局的第一参考。**

## 何时使用

- 把单体脚本拆成多个文件，或新建一个文件。
- 建立或调试 `MapScript.galaxy` → `scripts/main.galaxy` 引导链。
- 把 UI 面板、多段内容或第三方代码组织进子目录。
- 搭建或编辑 `Enums.galaxy`、`GlobalVariables.galaxy`、`Header.galaxy`、`MapInit.galaxy`。
- 确认某个文件是否由编辑器生成、因而不能碰。

## 加载边界

- **本子技能拥有：** 文件结构、include 顺序、模块布局、MapScript.galaxy 引导链，以及 Galaxy 脚本项目的文件拆分
- **父根技能（`sc2-galaxy-scripting`）拥有：** 项目约定、schema/语法规则、真源（source-of-truth）、命名前缀
- **兄弟子技能拥有：** `galaxy-language-fundamentals`（语法/类型系统）、`galaxy-triggers-and-functions`（经由触发器（Trigger）的初始化链）、`galaxy-debug-data-catalog`（跨触发器状态存储）

## 核心规则

1. **前置条件：** 先加载 [`sc2-galaxy-scripting`](../../sc2-galaxy-scripting/SKILL.md) —— 项目级语法约束（局部变量提升（hoisting）、无 `++`/`--`、用 `while` 而非 `for`、include 路径不带扩展名）、真源规则、模块脚本边界与命名规范（`libMy_` 函数前缀、`libMy_g_` 全局前缀）都在那里；本子技能只拥有文件布局。
2. `include` 路径相对于**地图根目录**，且不带 `.galaxy` 扩展名。
3. 顺序有影响：文件只能使用更早 include 进来的东西。禁止循环 include，没有头文件守卫 —— 绝不要重复 include 同一文件。
4. `MapScript.galaxy`、`LibHASH.galaxy`、`LibHASH_h.galaxy` 由编辑器生成：绝不要往里写逻辑，编辑器保存时会覆盖。
5. 所有自定义逻辑放在 `scripts/` 下；自动生成的文件只负责接线库。
6. `main()` 只注册一个地图初始化触发器 —— 每个真正的初始化调用都属于该触发器的处理函数，写在 `MapInit.galaxy`。
7. 调用 include 链里更靠后才声明的函数，需要在 `Header.galaxy` 写前置声明，而 `Header.galaxy` 要在 `GlobalVariables.galaxy` **之后** include。
8. `Enums.galaxy`（纯常量）必须在 `GlobalVariables.galaxy` **之前** include，这样结构体数组长度才能用上这些常量。
9. 面板与分块：先 include 每个面板/分块文件，协调器（`UI-Main`、`Parts`）最后 include。
10. 每个功能一个处理文件，恰好一个公开的 `ModuleName_Init()`，其余全部 `static`。
11. 函数命名为 `SystemName_ActionName`，让调用点一眼看出所属文件。
12. 存成**带 BOM** 的 UTF-8 `.galaxy` 会在加载时报 `Scri: Script load failed: Function not found` —— 存不带 BOM 的 UTF-8。
